# ТЗ: порівняння телеметрії ДЗ11 та польоту AirSim

## Мета

Додати до наявного стенда окремий режим верифікації польоту. Він не змінює
алгоритм керування чи логіку місії: після запуску зіставляє траєкторію дрона,
записану AirSim, із координатами отриманої телеметрії ДЗ11, збереженими
параметром `--telemetry-log`. `simulation.json` залишається лише для відтворення.

## Вхідні дані

- Запис ДЗ11: CSV формату `hw11-telemetry-v1` із координатами, часом,
  висотою, швидкістю, напрямом та станом. Схема й запуск описані в
  [docs/HW11_TELEMETRY.md](docs/HW11_TELEMETRY.md).
- Факт: послідовність станів C++/AirSim із полями `run_id`, `sim_time`,
  `drone.x`, `drone.y`, одержана вебсервером під час одного запуску.
- Користувач підтверджує однакові початкові умови, систему координат та
  ділянку польоту. Формат не містить надійного ідентифікатора сценарію,
  тому автоматично підтвердити відповідність не можна.

## Перевірка та відображення

1. Сервер зберігає обмежену за розміром послідовність фактичних координат
   поточного запуску та надає її через read-only API.
2. Користувач вибирає CSV в окремому полі «Телеметрія ДЗ11»; файл читається
   локально браузером і не надсилається серверу. JSON ДЗ10 відхиляється.
3. Тимчасово обидва шляхи показуються на одному графіку наявної вебпанелі:
   запис ДЗ11 пунктиром і запис AirSim суцільною лінією. Окреме
   вебвікно не є бажаним остаточним інтерфейсом; перенесення в Unreal
   оцінюється після перевірки порівняння.
4. Виводяться кількість кроків, довжина й тривалість кожного шляху та
   геометрична розбіжність точок AirSim від записаної ламаної ДЗ11 у площині XY
   (середня, 95-й перцентиль, найбільша).
5. Якщо немає фактичних точок або файл некоректний, замість числа показується
   причина, без вигаданого результату.
6. Висота та швидкість зберігаються в журналі, але не входять до геометричних
   метрик. Звіт вказує `reference_source: hw11-telemetry-v1` та площину XY.

## Обмеження інтерпретації

- Геометрична розбіжність не є похибкою датчика або мережевою затримкою.
- Тривалості показуються окремо: їхнє співвідношення не ототожнюється з
  реальною затримкою, оскільки годинники симуляторів можуть працювати по-різному.
- Показник відстані до лінії ДЗ11 не доводить, що дрон пройшов ті самі
  точки в той самий час або в правильному порядку.
- Режим не оцінює влучання, не змінює команди руху чи скиду.

## Критерій приймання

На одному фактичному запуску інтерфейс одночасно показує обидва шляхи, явні
метрики розбіжності та повідомлення про обмеження їх інтерпретації. Для
некоректного або несумісного файла порівняння не видає числовий висновок.
Потрібен справжній журнал ДЗ11 із симулятора викладача. Синтетичний файл
перевіряє читання формату, але не замінює такий прогін.

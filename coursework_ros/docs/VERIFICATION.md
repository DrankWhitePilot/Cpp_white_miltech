# Перевірка перед здачею

Цей журнал відокремлює **виконані перевірки** від того, що ще треба
перевірити. Успішна збірка сама по собі не доводить роботу інтерфейсу чи
переносимість на інший комп'ютер.

Збірка AirSim C++ залежностей через наявний `build_coursework` також
завершилася з кодом 0. Попередження стороннього AirSim/MsgPack коду при
компіляції залишилися; це не помилки збірки курсової.

Команди повторної перевірки всередині контейнера, із кореня репозиторію:

```bash
source /opt/ros/jazzy/setup.bash
colcon --log-base log/coursework build \
  --base-paths coursework_ros \
  --build-base build/coursework \
  --install-base install/coursework \
  --packages-select coursework_guidance_ros \
  --cmake-args -DCOURSEWORK_REQUIRE_AIRSIM=ON \
    -DAIRSIM_ROOT=/шлях/до/AirSim-1.8.1
colcon --log-base log/coursework test \
  --base-paths coursework_ros \
  --build-base build/coursework \
  --install-base install/coursework \
  --packages-select coursework_guidance_ros
colcon --log-base log/coursework test-result \
  --test-result-base build/coursework --verbose
```

## Ще не підтверджено

- Справжній запис телеметрії ДЗ11 із симулятора викладача та порівняння
  з відповідним польотом AirSim. Перевірки записувача й читача виконані
  на синтетичних даних; це не приймальний прогін симулятора.
- Вплив файлового запису на час обробки пакетів ДЗ11 не вимірювався.
- Завантаження JSON-звіту порівняння: кнопка натиснута, але вбудований
  браузер не видав події завантаження; файл на диску не знайдено. Потрібна
  перевірка у звичайному Chrome/Edge перед заявою, що експорт працює.
- Повторний запуск після `ЗАКРИТИ` без перезавантаження ПК ще не
  перевірявся через користувацький сценарій. Стартовий скрипт повторно
  відкрив локальну панель.
- Встановлення з нуля на іншому комп'ютері. Наявний dev container не
  встановлює ROS 2 та AirSim автоматично; ці залежності треба підготувати
  окремо за `SETUP_WINDOWS.md`.
- Редагування сцени в Unreal Editor: є готова `WindowsNoEditor` збірка,
  але немає вихідного Unreal-проєкту сцени.

## Ручний приймальний сценарій для іншого користувача

1. На чистому запуску виконати `START_COURSEWORK.cmd`. Переконатися, що
   панель показує `Немає телеметрії` до запуску й що Docker/збірка
   перевірені без ручної зміни скриптів.
2. Обрати «Базовий тест Кола» й типовий набір параметрів; запустити AirSim.
   Переконатися, що відкривається сцена, оновлюється телеметрія, а після
   завершення з'являється новий рядок у `results/coursework_results.csv`.
3. Записати справжній CSV телеметрії ДЗ11 за `HW11_TELEMETRY.md`, вибрати
   його в полі «Телеметрія ДЗ11», підтвердити відповідність умов,
   координат і ділянки польоту та натиснути `ПОРІВНЯТИ З AIRSIM`.
   Переконатися, що видно **обидві** траєкторії, числові метрики й
   застереження про несинхронізований час.
4. Зберегти звіт JSON; перевірити наявність полів `metrics`, `airsim_run_id`,
   `reference_file`, `reference_source: hw11-telemetry-v1` та застереження.
   Окремо перевірити, що JSON ДЗ10, хибний CSV або
   відсутній запис AirSim показує причину, а не вигадане число.
5. Перевірити `ЗУПИНИТИ` та `ЗАКРИТИ`; повторити запуск без перезавантаження
   комп'ютера. Зберегти скриншот або коротке відео як демонстраційний доказ.

Поки пункти 1–5 цього приймального сценарію не пройдені на сторонньому ПК,
проєкт слід описувати як **перевірений в авторському середовищі**, а не як
повністю переносимий пакет «завантажив і запустив».
